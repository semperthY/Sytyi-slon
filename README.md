# Сытый слонъ

Сайт кафе на Next.js, React и TypeScript. Репозиторий содержит исходники и снимок данных. На Timeweb сайт работает как статический экспорт, а существующая PHP-админка обновляет данные на сервере.

## Локальный просмотр

```sh
npm ci
npm run build
cp -R data out/data
python3 -m http.server 8080 --bind 127.0.0.1 --directory out
```

Откройте http://127.0.0.1:8080/. Next.js копирует снимок фотографий и карту из `public/uploads/` в `out/uploads/`. Команда копирования добавляет снимок меню, настроек и галереи. Локальный просмотр обслуживает статическую часть сайта.

## Архив обновления Timeweb

Из корня репозитория выполните:

```sh
npm run build
python3 scripts/package-timeweb.py ../sytyi-slon-update.zip
```

Нужен Python 3.9+. Скрипт создаёт ZIP и список файлов `sytyi-slon-update.files.txt`. Проверьте список перед загрузкой. При добавлении нового маршрута или ресурса оформления скрипт останавливается на незнакомых путях. Добавьте нужные пути в правила упаковки после проверки их назначения.

На сервере меню использует `data/menu/*.json` и `uploads/menu/image-map.json`. Галерея использует `data/gallery.json`, а сайт читает `data/settings.json`. Архив обновления исключает `data/`, `uploads/`, `images/gallery/`, `admin/` и скрытые файлы. Корневые серверные файлы, включая `.htaccess` и PHP, остаются за пределами архива.

### Загрузка с телефона после согласования

1. Откройте «Файловый менеджер» Timeweb и найдите `public_html` нужного домена. Убедитесь, что есть рабочая резервная копия сайта.
2. Загрузите **архив обновления** в `public_html`. Через контекстное меню выберите «Извлечь» в текущую папку. Одноимённые файлы сайта будут заменены.
3. Откройте главную, меню, банкеты и галерею в приватной вкладке. Проверьте цены, фотографии и переходы. Войдите в админку и проверьте, что загружаются её разделы.
4. Храните полные резервные копии вне веб-корня. Архив обновления после проверки можно убрать из веб-корня вручную.

Справка [Timeweb по файловому менеджеру](https://timeweb.com/ru/docs/virtualnyj-hosting/podklyuchenie-k-serveru-hostinga/fajlovyj-menedzher/).

### Предыдущие сборки и возврат оформления

Сохраняйте ZIP и список файлов каждого выпуска. Оставьте прежние хешированные ресурсы `_next/static/` на время, пока у посетителей могут быть открыты страницы предыдущей версии. Для отдельной уборки составьте список старых файлов по манифестам выпусков и проверьте, что их не использует текущая сборка или выпуск для возврата. Удаление согласуется отдельно.

Для возврата обычного оформления распакуйте ZIP обычной версии, созданный тем же скриптом. Если праздничная версия добавила отдельный маршрут, его страницу и файлы данных маршрута потребуется убрать по списку праздничного выпуска. Сохраните изменения в серверных `data/`, `uploads/`, `images/gallery/` и `admin/`, сделанные за время праздников. Полный серверный бэкап нужен для аварийного восстановления данных.
